# ADR 0001: Выбор стека для PhotoAtlas

Дата: 2026-09-01

## Статус

Принят.

## Контекст

Нужно приложение, которое:

- работает локально;
- сканирует указанную пользователем папку;
- читает GPS-координаты из EXIF фотографий;
- красиво отображает фотографии на карте;
- имеет плавный кастомный интерфейс;
- потенциально может быть кроссплатформенным.

## Решение

Выбран следующий стек:

- **Tauri 2** — оболочка десктоп-приложения.
- **Rust** — системная логика: файлы, EXIF, кэш, миниатюры.
- **React** — интерфейс.
- **TypeScript** — типизация фронтенда.
- **Vite** — сборка и разработка фронтенда.
- **MapLibre GL JS** — отображение карты.
- **SQLite** — локальный кэш метаданных.

## Причины

- Лёгкое десктоп-приложение по сравнению с Electron.
- Быстрая файловая обработка на Rust.
- Богатая экосистема для карт в JavaScript/TypeScript.
- Возможность сделать красивый кастомный интерфейс.
- Локальная работа без обязательного облака.

## Альтернативы

### Flutter

Плюсы:

- хорошая кроссплатформенность;
- отлично подходит для мобильных приложений.

Минусы:

- для карт и веб-подобного интерфейса экосистема может быть менее гибкой;
- сложнее быстро использовать богатые веб-картографические библиотеки.

### Electron

Плюсы:

- очень простой вход;
- большая экосистема.

Минусы:

- более тяжёлое приложение;
- выше потребление памяти.

### Python + Qt

Плюсы:

- простой прототип.

Минусы:

- сложнее сделать современный плавный интерфейс;
- тяжелее упаковка;
- карта менее удобна по сравнению с веб-стеком.
